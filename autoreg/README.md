# grok-register (архивная копия)

Автоматизированная регистрация аккаунтов x.ai (Grok) с **бесплатным** обходом Turnstile.
Главный скрипт — `grok_auto.py`: регистрация + **автоматическая конвертация SSO → CPA-токен**
после каждого успешного аккаунта.

## v5 — что улучшено (сравнение с v4)

Копия v4 + бэкпорт проверенных механик из v2/v3 + эксперимент с camoufox.

**Скорость / ресурсы:**
- Ферма Turnstile: Chromium теперь на **персистентном профиле** `.chrome-profile`
  + авто-порт (способ v3): `cf_clearance` переживает перезапуски — меньше
  челленджей на холодном старте; конфликта с Chrome пользователя нет.
- HTTP-сессия воркера **живёт между аккаунтами** (v3): минус TLS-хендшейк на
  аккаунт; куки чистятся на каждый аккаунт + warm-up ради свежего `__cf_bm`;
  при 403/503 и сетевых исключениях сессия пересоздаётся.
- Адаптивный опрос ящика (v2): первый заход через 2 с (в v4 — 4 с), окно ~110 с
  (в v4 — ~59 с) — меньше ложных «код не получен».
- `--cpa-threads` (дефолт 2, env `CPA_THREADS`): два параллельных воркера
  CPA-конвертации вместо одного — auths/ успевает за темпом 100+ акк/ч.

**Устойчивость:**
- IP-cooldown breaker в ферме (из v2): 3 пустых батча → ремонт страницы;
  6 подряд → охлаждение IP 300 с (×2 до 900 с). В v4 ферма долбила CF.
- `dead`-событие фермы: браузер/страница 3 раза подряд не поднялись → воркеры
  не ждут `get_token` (180 с) впустую, прогон завершается сразу.
- POST /sign-up через **PaceLimiter** (v3): минимальный интервал между сабмитами
  (`POST_INTERVAL`, дефолт 2 с) вместо жёсткого `post_lock` на время запроса.
- Исправлен баг v4: blacklist почтовых доменов **не работал** (модульная
  функция вызывалась через инстанс EmailService → AttributeError проглатывался
  except'ом). Теперь домен попадает в blacklist **после 2 фейлов** (в v4 — с
  первого; ложное срабатывание жгло пул доменов).
- `line_buffering` stdout (v2) — логи видны сразу при nohup/редиректе.
- Stats-поток: строка каждые 30 с (ok, темп акк/ч, очередь фермы, CPA-очередь,
  размер blacklist).

**Эксперимент camoufox (TS_ENGINE):**
- Реализован второй движок фермы на camoufox (антидетект-Firefox: geoip-локаль/TZ,
  персистентный профиль). С accounts.x.ai **не работает на 22.09.26**:
  turnstile `api.js` загружается (200, тело — настоящий JS) и исполняется
  (onload-инжект fires), но `window.turnstile` не появляется и естественный
  виджет не рендерится — тихий отказ анти-тампера. От настроек не зависит:
  голый `Camoufox(headless=False)` ведёт себя так же; встроенный uBlock Origin
  дополнительно режет 3p-скрипты (в движке отключён `exclude_addons`). Вывод:
  Firefox-базу этот Turnstile отклоняет. Движок оставлен под `TS_ENGINE=camoufox`
  для других целей; дефолт — `TS_ENGINE=drission`.

Новое в .env: `TS_ENGINE`, `POST_INTERVAL`, `CPA_THREADS` (см. .env.example).

## v5.1 — масштабирование на 6–8 потоков (22.09.26)

- **Ранний выход фермы**: `_batch_render` раньше ВСЕГДА выжидал
  `WIDGET_WAIT=75с`, даже если виджеты решились за 10с — ферма была узким
  местом (2.25 ток/мин при 4 потоках, очередь TS всегда 0). Теперь батч
  завершается сразу после решения всех виджетов: 6.6 ток/мин.
- **Дефолты**: `TS_BATCH` 3→6, `TS_MAX_QUEUE` 6→12 (глубже бессмысленно —
  токены протухают по TTL 240с), `.env THREADS` 2→6. **`TS_BATCH=8` не
  ставить**: 8 виджетов на странице → CF уводит весь батч в интерактивный
  челлендж (замер: производство падает 6.6→3.2 ток/мин, темп 365→172 акк/ч).
- **Фикс профиля (в v3/v5 не работал)**: `auto_port()` DrissionPage при
  запуске ПЕРЕЗАПИСЫВАЕТ `user_data_path` временным каталогом и удаляет его
  на disconnect (`_base/chromium.py`, handle_options/_on_disconnect) —
  `.chrome-profile` никогда не персистировал. Теперь свободный порт берётся
  самим скриптом (`_free_port()`), профиль реально переживает перезапуски
  (проверено: каталог 67 МБ живёт между прогонами).
- **Персистентный blacklist доменов**: `bad_domains.txt` рядом со скриптом,
  переживает перезапуски (раньше каждый прогон заново сжигал 2 цикла на
  мёртвый домен). `isco.eu.org` (мёртв 22.09) уже внесён; ожил — удалить
  строку.
- Замеры (эта машина, прогретый профиль, 22.09.26):
  * 4 потока, старая ферма: ~140 акк/ч (кампания 100)
  * 6 потоков: 15 акков за 3м09с ≈ **285 акк/ч**, очередь TS 11/12 (запас)
  * 8 потоков + TS_BATCH=8: ~172 акк/ч — интерактивный шторм, плохой режим
  * 8 потоков + TS_BATCH=6: 14 акков за 2м19с ≈ **365 акк/ч**, ноль скипов,
    CPA-воркеры (3) конвертируют в темпе; ферма впритык (очередь ~0) —
    при CF-волне просядет первой
- Рекомендация: `THREADS=6` повседневный режим (ферма с запасом),
  `--threads 8 --cpa-threads 3` — максимум темпа.

## Установка (чистая машина)

```bash
uv sync                          # все Python-зависимости из uv.lock
uv run patchright install chromium   # браузер для бесплатного обхода Turnstile (~150 МБ)

cp .env.example .env             # настройка конфигурации
mkdir -p keys auths
```

## Конфигурация (.env)

| Переменная | Описание |
|---|---|
| `EMAIL_PROVIDER` | Провайдер почты: `tmail` / `luckmail` / `gmail` / `outlook` / `fce` / `gptmail` / `mailtm` (по умолчанию `tmail`) |
| `GROK_PROXY` | **Оставить пустым** = прямой выход (системный VPN-туннель). Прокси с RU-выходом не подходят — гео-блок xAI |
| `YESCAPTCHA_KEY` | Не нужен — Turnstile решается бесплатно в браузере |
| `GMAIL_BASE_EMAIL` / `GMAIL_APP_PASSWORD` | Только для провайдера `gmail` |

## grok_auto.py — основной скрипт

Регистрирует аккаунты, сохраняет SSO в `keys/` и **сразу** чеканит CPA-токен в `auths/`.

```bash
# 1 аккаунт
.venv/bin/python grok_auto.py --count 1

# ограничение количества аккаунтов
.venv/bin/python grok_auto.py --count 10

# потоки (по умолчанию THREADS из .env или 2; капча решается впрок фермой —
# потоки больше не серийный замок, 2–4 реального ускорения)
.venv/bin/python grok_auto.py --count 20 --threads 3

# безлимит (по умолчанию, без --count)
.venv/bin/python grok_auto.py

# указать провайдера почты вручную
.venv/bin/python grok_auto.py --count 5 --email-provider tmail
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--threads N` | `THREADS` из .env (2) | Количество потоков (промпт убран — no-TTY безопасно) |
| `--email-provider X` | `EMAIL_PROVIDER` из .env | tmail/luckmail/gmail/outlook/fce/gptmail/mailtm |
| `--cpa-threads N` | `CPA_THREADS` из .env (2) | Фоновые воркеры SSO→CPA |
| `--post-interval S` | `POST_INTERVAL` из .env (2.0) | Мин. интервал между POST /sign-up |

Что происходит на каждый аккаунт:
1. Создаётся email (tmail — в **общем** патченом Chromium, живёт весь прогон).
2. Запрашивается и подтверждается код (gRPC-web).
3. Turnstile-токен берётся из **фермы**: фоновый поток на ОДНОМ браузере
   рендерит пачку виджетов `turnstile.render` и складывает готовые токены
   в очередь — регистрационные потоки не ждут капчу и не сериализуются.
4. Отправляется регистрация → SSO → `keys/grok.txt` + `keys/accounts.txt`
   (`email:password:sso`) + машинная строка `[SSO] email sso`.
5. PKCE-флоу (authorize → consent → code → token) выполняется **фоновым
   воркером** → `auths/xai-<email>.json`; поток регистрации не ждёт.

Архитектура ресурсов (версия 2) — замерено живыми прогонами 22.09:
- **2 Chromium на весь прогон вместо N+1** (ферма Turnstile + общий tmail):
  ~27 процессов Chrome, 2.5–3.2 ГБ RAM суммарно; после завершения —
  0 сирот. Раньше: новый Chromium на каждый email + перезагрузка страницы
  на каждую капчу.
- **Скорость: 48–67 с на аккаунт** (SSO + CPA-файл; 2 акк / 2 потока = 102 с
  стенок]; было ~5–9 мин/акк при серийной капче).
- Ферма: `TS_BATCH` виджетов за цикл (3), очередь готовых токенов до
  `TS_MAX_QUEUE` (6, TTL ~300 с, протухшие отбрасываются). Если виджет
  завис (интерактивный челлендж) — авто-клик по чекбоксу через 20 с.
- `--disable-gpu` НЕ используется: софтверный WebGL-отпечаток в headed-
  браузере может переводить Turnstile в интерактивный режим. Прочие
  ресурс-флаги (`--disable-extensions`, `--mute-audio`, …) безопасны.
- Домен temp-почты с недоходящими кодами автоматически попадает в чёрный
  список прогона (один фейл → ретраи идут на другие домены).
- `ca_fix.py`: копия CA-бандла в ASCII-путь — на Windows из кириллического
  каталога ВСЕ curl_cffi HTTPS-запросы падают (curl error 77), модуль обязателен.

Примечания:
- Первый аккаунт ~1 мин (подъём двух браузеров + первый батч капчи ~30 с),
  дальше конвейер: ящик → код → токен из очереди → сабмит.
- CPA-конвертация идёт в фоне и не удлиняет цикл; в конце main() дожидается
  воркера конвертаций (join с таймаутом 320 с) — auths-файлы дописываются.
- `kill_orphan_chrome.ps1` — утилита: убивает Chrome-сироты с remote-debugging
  (после убитых прогонов; Chrome пользователя не трогает).

## sso_to_cpa.py — догонка после grok_auto

**Обязательно запускать после каждого прогона `grok_auto.py`** — он находит аккаунты,
для которых первичная конвертация SSO → CPA не сработала (ошибка, обрыв, rate-limit),
и конвертирует их. Уже сконвертированные аккаунты пропускаются автоматически.

```bash
# догонка всех не сконвертированных (3 потока по умолчанию)
.venv/bin/python sso_to_cpa.py --all --threads 3

# проверка без конвертации: сколько осталось
.venv/bin/python sso_to_cpa.py --all --dry-run

# один конкретный аккаунт
.venv/bin/python sso_to_cpa.py --sso <sso_token>
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--all` | — | Конвертировать все SSO из `keys/accounts.txt`, пропуская готовые |
| `--threads N` | `3` | Параллельных воркеров (при rate-limit снизить до 2) |
| `--dry-run` | — | Только показать, что осталось сконвертировать |
| `--sso TOKEN` | — | Конвертировать один SSO |

Проверка «уже сконвертировано» выполняется **перед каждым** аккаунтом (по наличию
`auths/xai-<email>.json`) — повторные прогоны безопасны.

## grok_free.py — резервный скрипт (безлимит)

Если `grok_auto.py` по какой-то причине не подходит — бесплатный скрипт без авто-CPA:

```bash
.venv/bin/python grok_free.py            # безлимит, интервал 8–25 с
.venv/bin/python grok_free.py --count 10 # ограничение
```

Результат — только SSO в `keys/` (затем догонка через `sso_to_cpa.py --all`).

## Выходные файлы

| Файл | Содержимое |
|---|---|
| `keys/grok.txt` | SSO-токены (по одному на строку) |
| `keys/accounts.txt` | `email:password:sso` |
| `auths/xai-<email>.json` | CPA: access_token, refresh_token, expires_in (~21600 с) |
| `.action_id.cache` | Кэш Action ID (фолбэк при сбое сканирования) |

## Поддерживаемые модели

| Модель | Возможность | Как получить |
|---|---|---|
| `grok-4.5` | Чат + reasoning + поиск, 1M выходных токенов | SSO → Device Flow → OAuth direct |
| `grok-4.6` | Чат + reasoning + поиск, 500K контекст, long-running агенты, reasoning `xhigh` | SSO → Device Flow → Build-пул |
| `grok-chat-fast` / `grok-imagine-image` | Чат (быстрый) / генерация изображений | SSO → Web-пул |

OAuth Device Flow scope: `openid profile email offline_access grok-cli:access api:access`.

## ⚠️ Дисклеймер

Инструмент предназначен только для образовательных и исследовательских целей.
Регистрация аккаунтов и использование временных почт может нарушать Условия
обслуживания платформ (xAI/Grok, Google, Microsoft); аккаунты могут быть заблокированы.
В ряде стран массовая регистрация и обход верификации могут быть незаконными —
пользователь несёт полную ответственность. Никогда не коммитьте реальные учётные
данные в репозиторий.
